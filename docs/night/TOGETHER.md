# Night Together: сервер и основа комнат

В Night 0.13 подготовлены друзья по ID и комнаты. Это отдельная локальная идентичность профиля, без регистрации по почте. Запрос дружбы требует подтверждения получателя. Комнату создаёт один участник, приглашать можно только подтверждённых друзей; вход требует приглашения. До восьми участников. Создатель передаёт состояние воспроизведения с номером ревизии и серверным временем; чужие и устаревшие команды отклоняются.

Этот этап **не синхронизирует плееры сайтов автоматически**. В интерфейсе доступны создание комнаты по ссылке, приглашения, вход, открытие видео и выход. Следующий этап — привязка выбранной вкладки и адаптеры HTMLMediaElement/YouTube для play/pause/seek с учётом буферизации и часов. DRM и авторизацию сайтов обходить нельзя: каждому нужен собственный доступ к контенту. Передача экрана/файла не реализована.

## Что нужно разместить

Адрес клиента — `https://browser.night-watchers.com`, сервер — `144.91.104.48`. Нужны Docker Engine, Compose v2, DNS A-запись и доступные порты 80/443. В серверный архив включены Dockerfile, compose.yaml, Caddyfile и `services/together/INSTALL.md` с командами. Сервис разворачивает владелец сервера; удалённая установка из среды разработки не выполнялась.

Compose поднимает сервис под непривилегированным пользователем Node и Caddy с автоматическим HTTPS. Данные — в отдельном volume, корневая файловая система приложения read-only, порт 8787 не опубликован. Код сервера не требует npm-зависимостей. Для закрытого пилота можно начать с VPS 1 vCPU / 1 ГБ RAM; нагрузка не измерялась.

Сервер передаёт состояние и выбранную ссылку, а не видеопоток. Один процесс работает с одним JSON-файлом. Хранение атомарное через временный файл и rename; изменения последовательны. Мультипроцессное размещение на одном файле не поддерживается; при росте нужна транзакционная база.

Сервис не доверяет X-Forwarded-For: встроенный лимит за прокси считается на весь прокси. Для публичного запуска нужны отдельные proxy-лимиты, защита регистрации, мониторинг, резервные копии и процедура удаления/восстановления ID. Сейчас это основа закрытого пилота.

## Подключение

В «Друзья и комнаты» нажимается «Получить мой ID». В сборке закреплён `https://browser.night-watchers.com`; адрес не нужно вводить. Установка сервера описана в `services/together/INSTALL.md`. Для разработки адрес меняется через `night.together.server` в about:config; пустое значение возвращает поле ввода. Дальше пользователь копирует ID и добавляет друга по ID на том же сервере. Получатель принимает запрос. Для проверки на одном ПК допускается `http://127.0.0.1:8787`; удалённые адреса требуют HTTPS.

Профиль хранит ID, секретный ключ и адрес сервера в `night-together.json`. Ключ не показывается в UI, не отправляется в Mozilla Sync и не импортируется из Zen. Резервная копия профиля переносит эту идентичность. Кнопка отключения удаляет локальный ключ: без копии ID не восстановить; серверную запись она пока не удаляет.

Сервер хранит ключи доступа, ID друзей, запросы, приглашения и выбранную ссылку/позицию комнаты. Не передаются cookies, пароли, история и содержимое вкладок. ID имеет 64 случайных бита; секрет — 256 бит. ID сам по себе не даёт доступ к аккаунту. API требует Bearer-ключ; нет CORS-разрешения для сторонних сайтов. Рекомендуется не делиться ссылками с приватными query-токенами: участники и оператор сервера видят выбранный URL.

## API v1

- `POST /v1/register {}` → `{id, token}`.
- `GET /v1/state` с `Authorization: Bearer <id>:<token>` → друзья, запросы, приглашения, своя комната, serverTime.
- `POST /v1/action` с тем же ключом → friend-request/accept/decline/remove, room-create/invite/join/leave/state.
- Команда room-state: `{type, room, revision, position, paused}`; автор — создатель, revision совпадает с текущей. Ответ содержит новую ревизию и updatedAt. Текущая позиция при воспроизведении выводится из position и elapsed server time.

Открытый видимый раздел обновляется раз в пять секунд и по кнопке. Скрытая страница не опрашивает сервер; при выходе из раздела таймер удаляется. Неизменившиеся данные не перестраивают форму. Событийный транспорт, присутствие, уведомления и компенсация задержки ещё не подключены. Регрессионный тест запускает настоящий HTTP-сервис и проверяет согласие на дружбу, недоступность чужой комнаты, роли, ревизии, сохранение после перезапуска и исключение участника при удалении из друзей.
