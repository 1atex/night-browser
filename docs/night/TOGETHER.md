# Night Together 0.14

Клиент использует `https://browser.night-watchers.com`. Сервер разворачивается в Docker пользователем noon, за существующим reverse proxy. Обновление backend сохраняет старые ID, токены, друзей и приглашения. Команды без sudo и без повторной настройки nginx приведены в services/together/INSTALL.md.

## Друзья и внешний вид

Запрос дружбы требует подтверждения. Публичный ID состоит из 16 случайных hex-символов, секрет доступа — из 64. Имя (1–40 символов), цвет и значок публикуются только явной командой «Сохранить имя и аватар». Сервер возвращает ограниченный набор полей профиля; токены не попадают в список людей. Фото и произвольные ссылки на аватары не загружаются. Локальное название браузерного профиля не публикуется автоматически.

Ключ и endpoint находятся в night-together.json текущего Gecko-профиля. Этот файл исключён из Zen-импорта и Mozilla Sync. Резервная копия профиля переносит идентичность; «Отключить ID» удаляет локальный ключ, а не серверную запись.

## Просмотр

После создания комнаты по явной HTTP(S)-ссылке и приглашения каждый участник нажимает «Смотреть вместе». Вкладка связывается с одной комнатой; повторный запуск возвращает существующую вкладку. Пауза, play, seek и playbackRate ведущего публикуются по событиям и каждые пять секунд. Участник получает состояние примерно раз в секунду, учитывает серверное время и половину RTT, исправляет крупное расхождение перемоткой и небольшое — временной поправкой скорости. Время ПК участников не используется как общая временная шкала.

При буферизации ведущего участники приостанавливаются. Ошибка связи ставит привязанный плеер на паузу без перемотки к нулю; устаревшее более 15 секунд состояние ведущего тоже приостанавливает гостя. Автозапуск соблюдает правила сайта/Gecko: если он запрещён, пользователь нажимает Play вручную. Ведущий может явно сменить URL; клиент проверяет web-схему перед переходом. Самовольная навигация связанной вкладки останавливает синхронизацию, не публикуя новый URL.

JSWindowActor подключается только к верхнему документу выбранной web-вкладки после команды пользователя. Обработчик допускается в web-процессы через safeForUntrustedWebProcess, а parent принимает только ограниченные числовые данные от актёра текущей сессии. Токены сервера не передаются странице. Приватные окна исключены. После закрытия вкладки/окна или остановки просмотра удаляются обработчики и таймеры. Вне просмотра постоянного фонового опроса нет; видимый раздел друзей обновляется отдельно раз в пять секунд.

В рамках CI два настоящих процесса Gecko воспроизводят локальный HTML5 WebM и проверяют play/pause, seek, скорость, смену источника, отключение/перезапуск сервера, сохранение ID/имени, закрытие вкладки и приватный режим. Это не проверка живого YouTube-аккаунта, рекламы, DRM, iframe и live-потоков. Каждый участник получает видео напрямую с сайта со своим доступом. Сервер не передаёт экран, файлы, голос или видеопоток.

## Backend

Node 22, встроенный HTTP-сервер без npm-зависимостей. Один процесс и один JSON-файл в volume. Изменения последовательны, запись через временный файл и rename. Максимум 10 000 ID, 100 друзей/запросов, 20 приглашений и восемь участников комнаты. JSON-тело ограничено 8 КиБ. Проверяются Bearer-ключи, подтверждение дружбы, приглашение на вход, роль ведущего и ревизия команды.

За reverse proxy лимит считается по адресу proxy: до 6000 запросов в минуту, регистрация — до пяти в минуту. Нельзя считать это защитой от распределённой атаки. Публичный масштаб требует отдельных пользовательских лимитов, защиты регистрации, базы с транзакциями, мониторинга и восстановления/удаления аккаунтов.

## Совместимость API

URL API остаются v1, snapshot имеет protocol=2. Старые клиенты продолжают работать с id/friends/incoming/outgoing/invitations/room. Новые получают self и people с name/color/icon. Существующий JSON не требует сброса: отсутствующие поля получают безопасные значения по умолчанию.

- POST /v1/register → id/token.
- GET /v1/state с Bearer id:token → snapshot и serverTime.
- POST /v1/action → friend-request/accept/decline/remove, profile-update, room-create/invite/join/leave/source/state.
- profile-update: name, color, icon из ограниченного набора.
- room-source: room, url; только создатель, позиция сбрасывается и ревизия повышается.
- room-state: room, revision, position, paused, rate, buffering. Только создатель; revision должен совпасть. Старые команды без rate/buffering принимаются как rate=1/buffering=false.

Сервер хранит выбранную ссылку, позицию, имена и отношения. Cookies, пароли, история и содержимое остальных вкладок не отправляются. Не используй ссылки с приватными query-токенами: выбранный URL видят участники и оператор сервера.
