# Night Together 0.15.1

Исправление запуска комнаты и приглашений при отложенной загрузке JavaScript. Совместимо с Night Browser 0.15.0; обновляется только Docker-сервис.

На публичной странице Cloudflare Rocket Loader заменял type="module" у room.js и откладывал выполнение. Страница могла пропустить ранний NightRoom:Available: ручные запросы bridge работали, но список участников оставался пустым и RTC peer не создавался. Повторный сигнал в консоли восстановил чат на обоих реальных ПК.

- Страница сама проверяет готовность bridge, независимо от события. Повторные попытки ограничены и очищаются при закрытии.
- Скрипты исключены из Rocket Loader атрибутом data-cfasync="false" и отдаются с no-transform. Для комнаты и приглашений отключено хранение HTML; URL JS имеют новую версию. Настройки Cloudflare/nginx остаются прежними.
- Кнопки доступны после получения состояния, подписи показывают соединение/ожидание, а не успешный чат до открытия канала. CSP сохраняет script-src 'self' без unsafe-inline.
- Исправление не добавляет TURN и не меняет сетевые ограничения P2P.

Установка — services/together/INSTALL.md внутри ZIP. После docker compose up -d --build together на обоих ПК перезагрузи страницу комнаты Ctrl+Shift+R и снова подключи чат. ID и друзья сохраняются; переустановка браузера не нужна.

Проверено: 81 проверка Node; старый код не проходил нативный сценарий async-скрипта, запускающегося после DOMContentLoaded. С исправлением тот же сценарий прошёл вход по приглашению, чат и двусторонний RTP на двух Gecko, включая выход во время запроса микрофона. Публичный HTML до обновления подтверждённо содержал переписанный Rocket Loader тип скрипта. Пользователь подтвердил восстановление чата при повторном NightRoom:Available на обоих ПК.
